# よくあるエラーと対処

現場で多かったのは **モジュールを 2 か所に入れてない**ことと、そのあと **`npm run dev` を繰り返す**こと。型エラーは起動コマンドの問題ではなく、install 不足が多い。

---

## 先にやること（エラーを見た瞬間）

1. `npm run dev` はしない
2. エラーに `renderer/production`・`three`・`TS70` が出ていたら、`app/renderer/production` の `node_modules` を疑う
3. 足りない側で `npm ci` をやり直す
4. 入ったか確認してから、`app` で `npm run start:production` または `start:production:preview`

```powershell
Test-Path app\node_modules\electron
Test-Path app\renderer\production\node_modules\three
Test-Path app\renderer\production\node_modules\@types\react
Test-Path app\renderer\production\node_modules\@types\three
```

どれかが `False` なら、その階層で `npm ci`。[インストール.md](./インストール.md) の流れに戻る。

---

## TS7026（JSX の型が any / IntrinsicElements が無い）

**意味:** React の型（`@types/react`）が、画面プロジェクトから見えていない。

**よくある原因:**

- `app` だけ `npm ci` して、`app/renderer/production` を入れていない
- `production` の `npm ci` が途中失敗している
- 別フォルダ（`demo-0820` など）で install している

**対処:**

```powershell
cd app\renderer\production
npm ci
```

`@types/react` が入ったら `app` に戻し、[起動コマンド.md](./起動コマンド.md) の本番コマンドを使う。`npm run dev` は不要。

---

## Three が無い

表示例:

- `Cannot find module 'three'`
- `Failed to resolve import "three"`

**意味:** LIST 用の `three` が入っていない。

**原因:** `app/renderer/production` で install していない。`app` の `package.json` には `three` が無い（それで正しい）。

**対処:**

```powershell
cd app\renderer\production
npm ci
```

`node_modules\three` があることを確認してから起動する。

---

## TypeScript の型不足（TS7016 / TS2307 / TS2688 など）

| メッセージの例 | 足りないもの | 入れる場所 |
|----------------|--------------|------------|
| `Cannot find module 'three'` | `three` | `app/renderer/production` |
| `Could not find a declaration file for module 'three'` | `@types/three` | 同上 |
| `JSX.IntrinsicElements` / TS7026 | `@types/react` | 同上 |
| `Cannot find module 'react'` | `react` | 同上 |
| Node の `process` 型が無い | `@types/node` | `app` |

個別に `npm install @types/react` だけ足さなくてよい。そのフォルダで `npm ci` すれば lock どおり揃う。

`start:production` は内部で `renderer/production` の `tsc --noEmit` が走る。**型エラーが出る = 起動しない。** `dev` を回してもモジュールは揃わない。

---

## `npm run dev` を繰り返してしまう

| 実行した場所 | 実際に起きること |
|--------------|------------------|
| `app/renderer/production` | Vite の開発サーバだけ。4 画面 Electron は出ない |
| `app` | 本番 production ではない Electron が立ち上がることがある |

型エラー・Three 不足は **install し直す**以外では消えない。

現場の起動は次だけ。

```powershell
cd app
npm run start:production:preview
npm run start:production
```

## npm / Node の失敗

### `EBADENGINE` / engine が合わない

Node が古い。`node -v` が **v22.12 以上**か確認する。20 系は Electron 43 で失敗しうる。

### `npm ci` が lock で落ちる

そのフォルダに `package-lock.json` があるか確認する。現場クローンなら `app` と `app/renderer/production` の両方にある。無いならブランチが違う。

lock と `package.json` が食い違うときだけ、同じフォルダで `npm install`。

### `ECONNRESET` / `ETIMEDOUT` / network

会場ネットかプロキシ。同じフォルダで `npm ci` を再実行。Electron のダウンロードは時間がかかる。

### `electron` が見つからない

`app` で `npm ci` していない。`app\node_modules\electron` を確認する。

### `Cannot find module '.../dist/electron/main.js'`

`app` の TypeScript がまだビルドされていない。`cd app` → `npm run build`。`start:production` は続けて Electron も起動するので、install が完了していれば通常は自動。

## content 関連（install 成功後）

| 症状 | 対処 |
|------|------|
| LIST 画像が無い | USB の `content/images/` を載せる。`npm run check:production-content` |
| ANIMATION が流れない | `content/animation/LogoMotion_Trunk.mp4` |
| フォントがフォールバック | `content/fonts/`（Git には入っていない） |
| 4 window がタイル状 | ディスプレイ不足の fallback。4 面本番配置ではない |

画面配置は [docs/production/phase7-site-preflight.md](../docs/production/phase7-site-preflight.md)。

---

## まだダメなとき（切り分け順）

1. `node -v` が 22.12 以上か
2. 起動コマンドを `app` で打っているか
3. `app` と `app/renderer/production` の両方に `node_modules` があるか
4. `npm run dev` を使っていないか
5. USB の `content/` があるか
6. エラー全文（最初の `TS` 番号と `Cannot find module` のパス）を残す
