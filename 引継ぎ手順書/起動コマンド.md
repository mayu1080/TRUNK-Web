# 起動コマンド（現場）

作業フォルダは **`app`**。リポジトリ直下の `.bat` でも同じ。

`npm run dev` は現場では使わない（[よくあるエラー.md](./よくあるエラー.md)）。

---

## 現場で使う 3 本

| コマンド | 何が起きるか | いつ使う |
|----------|--------------|----------|
| `npm run start:production:preview` | **1 画面**。PRODUCT_LIST から始まる（AD / ANIMATION を飛ばす） | 配線前の UI 確認 |
| `npm run start:production:site` | **4 画面**。AD_IDLE から始まる。OS `display.bounds` に全面配置。現場の正 | 現場プレ実機の正 |
| `npm run start:production:preview:multi` | 4 window だが preview 扱い | 開発 PC で 4 枚の動きを見るとき。会場 4 面の合格には使わない |

ダブルクリックする場合（リポジトリ直下）:

| bat | 中身 |
|-----|------|
| `launch-production-preview.bat` | `start:production:preview` |
| `launch-production-site.bat` | `start:production:site`（現場の正） |

---

## コマンド例

```powershell
cd app
npm run start:production:preview
```

4 面:

```powershell
cd app
npm run start:production:site
```

起動コマンドは内部で次を順に行う。

1. `app/renderer/production` の型チェック（`tsc`）と Vite ビルド
2. Electron の Main をビルドして起動

ここで TS7026 や `three` 不足が出たら、起動コマンドを繰り返さず [よくあるエラー.md](./よくあるエラー.md) の install を直す。

---

## 使わないコマンド

| コマンド | 理由 |
|----------|------|
| `npm run dev`（`app`） | production の 4 画面起動ではない |
| `npm run dev`（`renderer/production`） | ブラウザ用 Vite だけ。Electron の 4 画面は出ない |
| `npm start`（`app`） | 開発用の既定 Electron。`TRUNK_DEMO=production` が付かない |
| `npm run start:0820` | 8/20 デモ |

---

## 起動前に一度だけ（任意）

```powershell
cd app
npm run check:production-content
```

`content/` の欠落を見る。USB を載せる前だと失敗して正常。

TypeScript だけ確認するなら:

```powershell
cd app
npm run build
npm run build:production
```

`build:production` は画面の型チェック込み。ここで落ちるなら `renderer/production` のモジュール不足が多い。

---

## 起動後の最低確認

**preview（1 画面）**

- ウィンドウが 1 枚
- LIST が見える（USB の list 画像）
- 管理画面用に 5 枚目は出さない

**production（4 画面）**

- content window が **4 枚**（LIST / 広告）。管理 PC には乗らない
- 余ったディスプレイに **管理コンソール**（認識モニター一覧）。これは 5 枚目の本番画面ではない
- 最初は **AD_IDLE**。`content/ads/` の mp4 が流れる（ファイルが無いときはプレースホルダ）
- 広告を触ると 4 面とも ANIMATION → LIST

Debug は画面にフォーカスして `D` → `P`。詳細は [docs/production/production-runtime-spec.md](../docs/production/production-runtime-spec.md)。
