# security.md（セキュリティ設計・草案）

> 本書は外注先がセキュリティ設計を作成・更新するためのテンプレートです。
> 実行環境が未確定の項目は、ローカルの `docs/open-questions.md` Q2 を先に確定してください（Git 管理外）。

## 1. 目的・スコープ

- キオスク型・複数モニター展示システムのセキュリティ要件を定義する
- オフライン/ローカル前提か、更新経路があるかを明確化する

## 2. 信頼境界（要確定）

| 境界 | 想定（TBD） |
|------|-------------|
| 端末内部 | アプリ / OS / キオスクシェル |
| ローカルネットワーク | 4面同期用通信の有無 |
| インターネット | 接続するか（原則オフライン推奨か） |
| 運用者 | コンテンツ更新・設定変更 |

## 3. 論点（外注が設計すべき項目）

### 3.1 端末ハードニング（キオスク）

- [ ] 開発者ツール・ブラウザUIの無効化
- [ ] ファイルシステムへの不要アクセス制限
- [ ] USB等による脱出防止
- [ ] 自動ログイン / 自動起動の権限最小化

### 3.2 通信セキュリティ（4面同期）

- [ ] 同期プロトコル選定時のなりすまし・改ざん対策
- [ ] ローカルLANのみに閉じるか
- [ ] 暗号化の要否（TLS / 共有鍵）

### 3.3 コンテンツ整合性

- [ ] `assets/` の改ざん検知（ハッシュ / 署名）
- [ ] 更新手順（誰が・どの経路で配置するか）

### 3.4 ログ・プライバシー

- [ ] 記録してよいイベント（エラー、遷移ログ等）
- [ ] 記録してはいけない情報（個人を特定しうる操作ログ等）
- [ ] ログの保存場所・保持期間

### 3.5 依存関係・脆弱性

- [ ] 依存ライブラリの選定方針
- [ ] CVE 対応・パッチ適用フロー

### 3.6 外注・リポジトリ運用

- [ ] 秘密情報をリポジトリに含めない（`.env` 禁止）
- [ ] Private リポジトリ + 最小権限アクセス
- [ ] Issue/PR に実メディア・顧客情報を貼らない

## 4. リポジトリ現状のセキュリティメモ

| 項目 | 現状 |
|------|------|
| 認証情報 | リポジトリ内になし（`.gitignore` で `.env` 除外） |
| 実メディア | 未同梱（`assets/.gitkeep` のみ） |
| Git 履歴 | 旧試作コードが履歴に残る可能性 → 外注共有時は履歴整理を検討 |

- [ ] 対策一覧（要件 / 実装 / 検証方法）
