> デモコードの枚数は**変更しない**（アセット都合で現状のまま）。

## 背景色

| 項目 | デモ（現状） | 本番方針 |
|------|-------------|----------|

## LIST 探索層 — グレースケールトーン

| 項目 | デモ（`cultish-soft`） | 備考 |
|------|------------------------|------|
| 課題 | 写真の黒が背景と同化しやすい | アートレビューで指摘済み |
| 対応 | `colorTone`（shadow `#2e2822` / highlight `#eee7d8`）+ `brightness: 1.32` + `contrast: 0.37` | Pixi v8 contrast は 0.5=標準。旧 0.86 はハイコントラストだった |
| IMAGE_ZOOM | DOM 上はフルカラー（変更なし） | LIST 仕様どおり |

本番でもトーンはコンテンツ写真の黒レベルに応じて `brightness` / `contrast` を微調整する想定。

## 浮遊画像枚数（本番推奨）

| 区分 | 枚数 | 理由 |
|------|------|------|
| **DD デモ（現状）** | 実アセット ~25 枚前後（`TARGET_IMAGE_COUNT=40` は DB 由来の目標値、デモは増複しない） | レビュー・AD 確認用。枚数はこのまま |
| **本番 LIST 探索** | **70〜80 枚** 推奨 | CULTISH 風の密度感・ワールドの「埋まり」に必要。合否基準も 70 枚 @ 55fps |

### 本番で増やすときの実装ポイント

1. **配置** — `spreadPlacement.ts` のフィールド配置（セル分割＋ジッター）は 70〜80 枚でもそのまま利用可。`sameGroupMinDist` / `anyMinDist` は密度に応じて微調整。
2. **ワールドサイズ** — 現デモ `3000×2200`、`defaultZoom: 0.86`。枚数増加時はワールド拡大または `boundsInset` 調整で重なりを回避。
3. **GPU** — グレースケールは **ワールド単位 1 フィルタ**（per-sprite フィルタ廃止済み）。70〜80 枚でもフィルタコストは一定。
4. **テクスチャ** — thumb 解像度上限・非同期 decode・4 面同時の GPU メモリは `product-list-demo-strategy.md` 合否基準で検証。
5. **データ** — `assetIndex` + `getContentFileUrl` から LIST 掲載画像を供給。デモの `demo-asset-index.json` 複製は本番では不要。

### 関連定数（デモのみ・本番は別設定）

```
DD-pixi-three-style/src/pixi/constants.ts
  TARGET_IMAGE_COUNT = 40   // デモ負荷目安（本番 70〜80 とは別）
  MAX_IMAGE_COUNT = 70      // 上限の参考値
```

本番では `architecture.md` / content スキーマ側に「LIST 探索表示枚数: 70〜80」を明記すること。
